# AI 代码安全审计复核清单：让每条发现都有证据

让 AI 检查代码，拿到一份漏洞报告，只完成了发现问题的一步。Cloudflare 官方仓库介绍了一套六阶段审计流程，把候选问题验证与最终记录复核分别交给独立执行者；官方明确要求，验证者不能是发现者。[来源：官方仓库](https://github.com/cloudflare/security-audit-skill)

我们的判断是：小团队最值得复用的，是“主动找反证”的复核方式。验证者需要检查攻击前提、实际调用路径和已有防护，不能只把发现者的解释改写一遍。

这份材料提供可复制的测试设计与记录模板，**本轮未执行产品实测，不包含效果排名。没有发现漏洞，不等于代码安全。**

## 先把角色分开

| 角色 | 负责什么 | 交付什么 |
|---|---|---|
| 测试负责人 | 固定测试代码、隐藏答案、统一条件 | 测试说明、缺陷真值表、运行配置 |
| 发现者 | 审查代码，提出候选问题 | 位置、攻击路径、成立前提、证据 |
| 独立复核者 | 从源码重新检查，尝试推翻候选结论 | 确认、驳回或待验证，以及依据 |
| 结果核对者 | 对照隐藏答案，处理重复与遗漏 | 确认、误报、漏报、待验证和成本记录 |

发现者可以补充证据，但不能独自批准自己的发现。独立复核至少要使用新的会话或执行上下文；换一个角色名称、继续沿用发现者的推理，不算独立复核。

使用不同模型可以作为额外对照，但不能据此认定结论正确。最终仍要看源码、测试和可重复的证据。

## 设计一份含已知缺陷的测试代码

建议使用一个本地运行的小型业务服务，覆盖登录、资料查询、文件读取和外部请求等常见入口。只使用虚构账号与测试数据，不接生产系统。

### 测试样本设计表

以下是**待制作的样本设计**，不是已经验证的漏洞。

| 测试模块 | 故意植入的缺陷 | 应能验证的行为 | 配套的安全对照 |
|---|---|---|---|
| 资料查询 | 查询对象时遗漏归属检查 | 普通测试用户能读取其他用户的测试资料 | 相同入口加入归属校验后拒绝访问 |
| 数据检索 | 外部输入直接拼接进查询 | 特定输入改变原定查询逻辑 | 使用参数绑定，输入被当作数据处理 |
| 文件读取 | 未限制解析后的路径范围 | 请求能够读取测试根目录之外的哨兵文件 | 解析路径后校验目录边界并拒绝越界 |
| 地址预览 | 服务端请求目标缺少约束 | 能访问测试约定中禁止访问的模拟内部端点 | 对目标和重定向后的地址实施约束 |

安全对照也要进入被审查代码，帮助检验工具是否会把“看起来危险的写法”一概报成漏洞。

### 隐藏答案怎么做

```text
缺陷真值表模板——仅测试负责人和结果核对者可见

缺陷 ID：
代码版本或提交：
模块与入口：
预期的访问权限或信任边界：
故意植入的缺陷：
攻击者需要具备的条件：
触发步骤：
预期观察结果：
对应测试及原始输出：
修复方式：
修复后回归结果：
容易混淆的安全对照：
```

制作时逐项检查：

- [ ] 缺陷位于实际可达的业务路径，不能只在无调用的函数里埋问题。
- [ ] 已用测试验证预期行为，不能仅凭设计者判断它“应该有漏洞”。
- [ ] 修复前能触发，修复后同样的输入被正确处理。
- [ ] 不在文件名、注释或测试名称中泄露缺陷答案。
- [ ] 安全对照已经验证，不能把未经检查的代码当作“安全真值”。
- [ ] 审查运行期间冻结代码，发现者和复核者均不得修改原始样本。
- [ ] 执行仅使用受限测试环境；外部请求由本地模拟服务承接。

**真值表描述的是已知植入缺陷，不是整份代码的全部漏洞。** 工具报告了真值表之外的问题，应独立验证，不能直接算误报；工具没有命中某项植入缺陷，也不能靠相近关键词算作发现。

## 怎样做公平对照

对照对象可以设为“普通审查”和“使用该技能的审计流程”。普通审查也要拿到清晰任务与合理预算，不能故意使用含糊提示词拉低表现。

| 项目 | 普通审查 | 技能流程 |
|---|---|---|
| 代码与运行环境 | 相同冻结版本 | 相同冻结版本 |
| 可见资料 | 业务说明、权限规则、允许的操作 | 相同资料 |
| 模型与工具权限 | 预先记录 | 尽量保持一致，差异必须记录 |
| 预算 | 预先固定 | 采用相同预算口径 |
| 隐藏答案 | 不提供 | 不提供 |
| 候选问题记录 | 保留原始输出 | 保留原始输出 |
| 最终结果核对 | 使用共同复核规则 | 使用共同复核规则 |

执行前选定比较口径：

- **预算相同：**比较在相同成本或时间限制内，各自找到了什么。
- **完整流程：**允许各自跑完，比较最终结果和全部成本。

不要让一组受时间限制、另一组无限运行，再把结果解释成流程优势。若技能流程包含内部复核，必须计入其成本；共同复核者仍需按统一标准检查双方提交的候选问题。

## AI 审查后的复核清单

### 范围与上下文

- [ ] 记录了代码版本、配置、依赖和实际审查范围。
- [ ] 明确了用户角色、对象归属和权限规则。
- [ ] 标出了未读取、无法运行或未覆盖的部分。
- [ ] 区分了源码结论、运行观察和待验证假设。

### 每个候选问题

- [ ] 指向具体文件、位置和相关代码。
- [ ] 说明攻击者能控制什么输入、需要什么权限。
- [ ] 从入口追踪到危险操作或边界突破。
- [ ] 检查中间是否已有校验、权限限制或其他有效防护。
- [ ] 描述实际影响，不只使用“可能高危”等形容词。
- [ ] 保留触发步骤、输入和原始输出。
- [ ] 运行结果能支持报告声称的影响范围。
- [ ] 无法执行验证时，写明缺少的确切事实。

### 独立复核

- [ ] 复核者未参与该候选问题的发现。
- [ ] 复核者自行读取相关源码，没有直接接受原报告的推断。
- [ ] 主动尝试证明路径不可达、权限不足或已有防护有效。
- [ ] 确认结果可以重复；驳回结果有明确反证。
- [ ] 新证据导致结论发生实质变化时，再做独立检查。

### 修复与交付

- [ ] 合并同一根因导致的重复报告，同时保留受影响入口。
- [ ] 修复后重跑原触发步骤，并检查正常业务流程。
- [ ] 保留修复前后的差异与测试证据。
- [ ] 最终报告包含待验证项和未覆盖范围。
- [ ] 没有把“本次未发现”写成“系统安全”。

## 记录确认、误报、漏报和成本

### 候选问题记录表

```markdown
| 候选 ID | 来源运行 | 位置与根因 | 成立前提 | 复现证据 | 独立复核结论 | 理由或缺失事实 | 对应真值 ID |
|---|---|---|---|---|---|---|---|
| 待填 | 待填 | 待填 | 待填 | 待填 | 确认／驳回／待验证 | 待填 | 待填或新增发现 |
```

口径固定为：

| 分类 | 判定依据 |
|---|---|
| 确认 | 独立证据支持边界突破及报告所述影响 |
| 误报 | 候选被有效反证推翻；仅仅没能复现，不足以判为误报 |
| 漏报 | 已验证的植入缺陷，在本次审查提交的候选中没有对应项 |
| 待验证 | 缺少判断成立与否的必要事实，暂不能确认或驳回 |
| 重复 | 多份候选指向同一根因，不重复计为独立漏洞 |

若候选命中了已知缺陷，但复核仍未完成，应单列“已命中、待确认”，不能计入确认发现，也不能隐藏在漏报统计里。

### 对照汇总表

```markdown
| 运行标识 | 审查方式 | 已知缺陷确认命中 | 新增确认问题 | 误报 | 未报告的已知缺陷 | 待验证 | 重复 | 未覆盖范围 |
|---|---|---|---|---|---|---|---|---|
| 待填 | 普通审查／技能流程 | 待填 | 待填 | 待填 | 待填 | 待填 | 待填 | 待填 |
```

### 成本记录表

```markdown
| 运行标识 | 模型与版本 | 调用量或 token | 审查用时 | 内部复核用时 | 共同复核用时 | 人工投入 | 实际费用 | 失败与重试 |
|---|---|---|---|---|---|---|---|---|
| 待填 | 待填 | 待填 | 待填 | 待填 | 待填 | 待填 | 待填或无法取得 | 待填 |
```

成本记录注意：

- 并行任务同时记录总耗时与各任务累计耗时，不能混用。
- 失败调用、重试和被驳回候选的验证，都属于成本。
- 实际费用无法取得时保留用量，不编造金额。
- 人工确认、搭建环境和处理异常的时间单独列出。
- 若展示比例，必须同时给出分子、分母和待验证数量；已知缺陷命中率不能代表真实项目的全部漏洞检出率。

## 可直接复制的提示词

### 给发现者

```text
请审查指定代码的安全问题。

输入：
- 代码版本：[填写]
- 审查范围：[填写]
- 业务权限与信任边界：[填写]
- 允许的工具与测试操作：[填写]
- 时间或费用预算：[填写]

要求：
- 从实际入口追踪输入、权限检查和关键操作。
- 对每个候选提供位置、根因、攻击前提、影响和证据。
- 检查已有防护，区分漏洞与一般加固建议。
- 不修改原始代码；测试只在指定隔离环境执行。
- 不把推测写成运行事实。
- 无法验证时，指出缺失的确切事实。
- 列出未覆盖范围。
- 不读取隐藏答案或其他审查运行的输出。

提交候选清单，保留原始证据，等待独立复核。
```

### 给独立复核者

```text
请独立复核以下候选安全问题，优先尝试推翻它。

你没有参与该问题的发现。不要直接沿用发现者的推理。

请自行检查：
- 入口和调用路径是否真实可达。
- 攻击者是否具备所需输入控制与权限。
- 中间是否存在有效防护。
- 证据是否支持所声称的影响。
- 测试环境是否引入了不适用于目标环境的条件。

输出：
- 结论：确认／驳回／待验证。
- 自行检查的源码位置和路径。
- 可重复的验证步骤与原始结果，或明确反证。
- 尚未解决的事实。
- 结论适用的代码版本、配置和范围。

证据不足时保留待验证，不以多数意见或模型自信程度代替证据。
```

### 给结果核对者

```text
请对照隐藏真值表、审查候选和独立复核记录，整理结果。

要求：
- 按根因和攻击路径匹配，不按关键词匹配。
- 对同一根因去重。
- 分开记录确认、误报、漏报、待验证和重复。
- 真值表之外的发现，独立验证后再分类。
- 单列已命中但尚未确认的已知缺陷。
- 保留原始记录与更正理由。
- 汇总审查、复核、重试及人工成本。
- 不从本次样本推导普遍检出率或安全保证。

输出候选明细、对照汇总、成本表和结论边界。
```

## 结论怎么写

下面的文字可在填入真实记录后使用：

```text
本次在[代码版本、配置与范围]内，对[审查方式]进行了对照。
确认结果、误报、漏报和待验证项见随附记录表。

本次结论仅适用于所列样本、运行条件和预算。
尚未覆盖的部分为：[填写]。
尚未解决的验证条件为：[填写]。

本次未发现的其他漏洞，不能据此认定不存在。
已知缺陷的命中情况，不能代表真实项目全部漏洞的检出能力。
```

不要用“零漏洞”“全面安全”“可以放心上线”替代有范围、有证据的结论。

## 附：自测靶场（拿去测任何 AI 代码审查工具）

下面是一个故意写坏的 49 行 Flask 小项目，**只用于本地学习测试，不要部署**。它预埋了 5 个已知缺陷和 1 个看起来可疑、其实安全的写法。把它交给你的 AI 审查工具，再对照答案统计：查出几个、漏了几个、误报几个。

预埋答案（先别看，测完再对）：

<details><summary>展开答案</summary>

- V1 SQL 注入：`/search` 把请求参数直接拼进 SQL。
- V2 硬编码凭据：`/private` 接受源码里的固定演示令牌。
- V3 路径穿越：`/download` 没有限制最终文件路径。
- V4 管理接口缺少鉴权：`/admin/users` 直接返回用户列表。
- V5 不安全反序列化：`/restore` 对请求体调用 `pickle.loads()`。
- S1 安全对照：`/safe-search` 用了参数绑定，不应被报成 SQL 注入。

</details>

```python
from flask import Flask, request, jsonify, Response
from pathlib import Path
import sqlite3
import pickle

app = Flask(__name__)
ROOT = Path(__file__).resolve().parent
DB = ROOT / "demo.sqlite3"
FILES = ROOT / "public"
ADMIN_TOKEN = "demo-public-fixed-admin-token"

def connection():
    return sqlite3.connect(DB)

@app.get("/search")
def search():
    name = request.args.get("name", "")
    with connection() as db:
        rows = db.execute("SELECT id, name FROM users WHERE name = '" + name + "'").fetchall()
    return jsonify(rows)

@app.get("/private")
def private():
    if request.headers.get("Authorization") != "Bearer " + ADMIN_TOKEN:
        return "", 403
    return jsonify({"private_note": "dummy confidential note"})

@app.get("/download")
def download():
    name = request.args.get("name", "")
    return Response((FILES / name).read_bytes(), mimetype="application/octet-stream")

@app.get("/admin/users")
def admin_users():
    with connection() as db:
        rows = db.execute("SELECT id, name, email FROM users").fetchall()
    return jsonify(rows)

@app.post("/restore")
def restore():
    value = pickle.loads(request.get_data())
    return jsonify({"type": type(value).__name__})

@app.get("/safe-search")
def safe_search():
    name = request.args.get("name", "")
    with connection() as db:
        rows = db.execute("SELECT id, name FROM users WHERE name = ?", (name,)).fetchall()
    return jsonify(rows)
```
