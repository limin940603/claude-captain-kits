# AI智能体编码协作自查清单

GitHub公布的新Git存储架构Rubicon，在其内部测试中支持5000个智能体并发协作、每秒7200次推送，读取延迟保持稳定。

架构将数据存储、引用状态管理、请求处理和后台维护拆开，适应更多智能体持续工作的负载。

下面是我们根据这条新闻整理的团队自查清单，可用于一人公司和小团队安排AI编码任务。

## 仓库与任务

- [ ] 已确认本次任务使用的仓库和起始分支。
- [ ] 已阅读项目说明、现有约定和当前进度。
- [ ] 已检查工作区，确认是否存在其他人的未提交修改。
- [ ] 已写清任务目标、允许修改的范围和完成标准。
- [ ] 不同任务使用独立分支；本地并行时，按需使用独立工作目录。
- [ ] 多个任务会修改同一文件时，已指定处理顺序或合并负责人。

## 权限与资料

- [ ] 已确认智能体使用的账号及其仓库权限。
- [ ] 权限与任务相符，读取任务无需额外授予写入权限。
- [ ] 已明确是否允许提交、推送、创建合并请求。
- [ ] 已明确合并、发布和部署分别由谁执行。
- [ ] 密钥、令牌和客户资料按项目要求保管，不进入代码提交。
- [ ] 需要调用外部接口或消耗额度时，已明确授权范围。

## 推送与合并

- [ ] 主分支保护规则已确认。
- [ ] 推送前检查当前分支及目标远程仓库。
- [ ] 提交内容只包含本次任务所需改动。
- [ ] 已检查差异，确认没有夹带凭据、临时文件或其他任务内容。
- [ ] 已按项目要求运行必要检查，并保存实际结果。
- [ ] 多个任务修改同一区域时，已检查合并冲突和行为冲突。
- [ ] 已指定合并前的检查负责人。
- [ ] 需要回退时，能定位对应提交和恢复方法。

## 自动流程与消耗

- [ ] 已确认一次推送会触发哪些检查、构建或部署。
- [ ] 已确认重复推送是否造成重复运行。
- [ ] 已明确自动流程失败后由谁处理。
- [ ] 涉及付费用量的流程，已安排查看消耗和异常情况。

## 交接记录

任务结束时填写：

- 任务目标：
- 分支与提交：
- 实际改动：
- 已完成的检查：
- 尚未验证的部分：
- 待处理问题：
- 下一步负责人：
