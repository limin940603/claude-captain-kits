# 「该不该上智能体」判断清单

> 用法：手上有一件想交给 AI 的活，先拿这五个问题过一遍。前三条都答"是"，先做固定流程；第一条答"否"，再考虑智能体。
> 依据：Miguel Ríos Berríos《You may not need an agent after all》（2026-10-31），以及 Anthropic 关于工作流与智能体选型的公开文章。文中数字均为原作者在虚构文件上的自测。

---

## 一、五个问题

### 1. 步骤能不能写死？
把这件活写成一张先后清单：第一步做什么、第二步做什么……
- 能写出来，而且每次都差不多 → **固定流程**。
- 写不出来，每次要看情况临时决定（研究、写作、调试） → 这才是智能体的活。
- 写了一半写不下去 → 能写死的部分做成流程，写不死的那一步单独交给智能体。

### 2. 每一题是不是只问一件事？
把需要模型判断的地方，拆成一个个"是 / 否"小问题。
- 错误问法："这份证书有没有应有的印章和签名？"（原作者实测：空白证书被判 0.93 的把握"有"）
- 正确问法："每个签名栏都已签署吗？"（同一张证书：0.07）
- 印章、签名区、每个日期，各问各的。拆开问反而准，也不贵。

### 3. 把握不够时，交给谁？
给每个问题设一条线：把握高于线判"过"，低于另一条线判"不过"，中间的**直接交给人**。
- 别让同一个模型再问一遍。原作者做过二次检查，从没改变过关键答案。
- 阈值先在一小批样本上调，再拿没见过的样本复测，防止调过头。

### 4. 有没有"死规则"？写成条文了吗？
有标准答案的东西（编号规则、日期格式、金额上限、名单是否在册），写进代码或表格，用程序判断。
- 不要问模型"这个编号前缀是不是某机构发的"。原作者实测：12 次只对 3 次。
- 模型负责"看"（这页有没有签名、有没有涂改），代码负责"判"（规则对不对）。

### 5. 第一次探出来的路，写成清单了吗？
没人走过的活，可以先让智能体慢慢做一遍。做完让它把步骤写下来，人审过再存。
- 下次先照清单走，走不通再叫智能体，把新情况补进清单。
- 清单存成普通文件（.md / 脚本），不锁在某一个工具里，换工具也能用。

## 三、可以直接发给 AI 的提示词

```
我有一件重复的活：【描述这件活，越具体越好】。
请帮我把它改成固定流程，不要设计成能自己规划的智能体：
1. 列出先后步骤，标明哪一步是普通工具/代码、哪一步需要模型判断。
2. 需要模型判断的地方，拆成"一题只问一件事"的是/否问题，每题要求返回把握程度（0–1）。
3. 给每个问题建议"判过 / 判不过 / 交人"的阈值，说明先怎么在小样本上调。
4. 把有标准答案的规则单独列出来，写成代码或表格，不交给模型。
5. 最后一步汇总成一份简短报告。
拿不准的地方先列出来问我，不要自己假设。
```

## 四、附：agentrun 命令原文（原作者开源的工具）

仓库：github.com/Parcha-ai/agentrun（Apache-2.0，目前是 beta）。下面命令照抄仓库 README（2026-11-04 核对），**我们没有实际跑过**，以仓库最新说明为准。

### 本机启动服务（需要 Docker 和模型 key）
```bash
docker run -d --name agentrun -p 127.0.0.1:7340:7340 -v agentrun:/data \
  -e AGENT_MODEL=openrouter/anthropic/claude-sonnet-5.5 -e OPENROUTER_API_KEY \
  ghcr.io/parcha-ai/agentrun-server:beta
docker logs agentrun | grep Open
```
- key 先放进环境变量 `OPENROUTER_API_KEY`，不要写进命令里；模型名可以换。
- 只监听本机 7340 端口。

### 无密钥试跑（看演示）
```bash
npm install @parcha/agentrun-dsl@beta
npx @parcha/agentrun-dsl@beta demo
```
- 需要 Node 22.19 以上。演示里的回答是写死的，不花钱。

### 跑客服示例（也不需要 key）
```bash
git clone --branch main --single-branch https://github.com/Parcha-ai/agentrun.git
cd agentrun
npm ci --ignore-scripts
npm run build
npm run demo:support
```
- 在克隆好的仓库里还可以：`npm run demo:support -- payment`（付款案例）、`npm run test:support`（跑测试）、`npm run demo:support -- unresolved`（转人工案例，正常结束时退出码是 2）。

### 注意
- 工作流里的代码节点以本机进程权限运行 JavaScript。别人写的工作流，先看过再跑。
- 真跑需要模型 key，按调用计费；先用无密钥演示看懂结构再接 key。
